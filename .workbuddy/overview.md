## 你指出的问题

切换 OpenAI ↔ Ollama 后，之前保存的内容全没了。

**根因**：切换服务商时我把整个表单重置了（provider、地址、模型全清）。这是设计错误——服务商只是同一张表单的两种形态，不是"切换另一个实体"，不该清掉用户已经填的东西。

## 按你的叙述重做后的样子

### 一块带边框的卡片

```
┌─────────────────────────────────────────────────────────┐
│ [OpenAI 兼容 | Ollama 本地]          [☰ 已保存配置 (2)]  │
├─────────────────────────────────────────────────────────┤
│ 配置名称                    │ 模型名                     │
│ [比如 百炼 / 公司 Ollama]   │ [deepseek-chat]            │
├─────────────────────────────────────────────────────────┤
│ 接口地址                    │ API-KEY                    │
│ [https://api.deepseek.com/v1] │ [••••••••••        👁]    │
├─────────────────────────────────────────────────────────┤
│ [测试连接]  [保存配置]      状态提示                       │
└─────────────────────────────────────────────────────────┘
```

- **配置名称**是新增的，保存后靠它下次选回来
- **API-KEY** 带眼睛图标：点一下在圆点和明文之间切换，显示时可以直接看和改；按你说的**没做复制按钮**
- 接口地址、模型名都是手动输入，输入框里给参考值
- **切换服务商不再清空任何已填内容**，地址为空时自动补 Ollama 默认地址

### 「已保存配置」按钮（provider 这一行最右侧）

点开是一个列表：每条显示配置名 +「OpenAI 兼容 / Ollama · 模型名」，点一下就载入，右侧垃圾桶可删，底部「＋ 新建配置」。

这些配置各自保存自己的 Key（加密存在本机 `ai-keys/` 目录下，按配置 id 分开），**不进数据库、不进备份**。

### 流程按你说的改成了：先测试，再保存

- 点「测试连接」→ 用的是**你刚填的临时 Key，不落盘**，只在这一次请求里用
- 测试通过 → 点「保存配置」→ 才写进配置列表、才把 Key 加密存下来
