## 二、Phase 3：AI 链路打通

### 主进程（`src/main/ai.ts`）
- **所有请求走主进程**：渲染进程看不到 Key，也不受 CORS / CSP 影响
- **Key 加密存储**：`safeStorage`（Windows DPAPI）加密到 `数据目录/ai-key.bin`，**不进数据库、不进备份**
- **流式请求**：SSE 逐块解析，`ai:delta` 事件实时推给渲染进程；支持 `ai:abort` 中途停止
- **获取模型列表**：OpenAI 兼容走 `/models`，Ollama 走 `/api/tags`
- Ollama 走 OpenAI 兼容路径（`/v1/chat/completions`），一套解析逻辑通吃

### 设置页（连接表单）
- 服务商切换（OpenAI 兼容 / Ollama 本地）→ 表单重置，Ollama 自动填 `http://localhost:11434/v1`
- 三个字段：接口地址、密钥（密码框，显示「已保存」状态）、模型名（带 datalist 下拉）
- **联动规则落地**：改地址 → 模型名清空；保存新 Key → 模型名清空并提示重选
- 「获取列表」一键拉模型；「测试连接」真实发一条消息，显示模型回话前 50 字
- 选远程模型时明确提示「上下文会发送到你填写的服务商」

### 上下文组装（`src/renderer/src/ai/context.ts`）
按定稿优先级，每次请求现场读库（改完档案下一次对话立刻生效）：
```
系统提示词 v2.1
+ 今天几号
+ 当前主要矛盾（含服务的目标）
+ 目标（按优先级）
+ 现状档案（按分类分组，最多 60 条）
+ 感悟（最近 12 条）
+ 长期记忆（有效状态，最多 20 条，自动提炼的带标记）
+ 最近 20 条对话
```
系统提示词落在 `src/renderer/src/ai/systemPrompt.ts`，含**草案输出协议**（要求 AI 在回答末尾附 `draft` 块，step 2–4 条、habit 0–2 条）。

### 首页（真实对话）
- 发送 → 存用户消息 → 组装上下文 → 流式渲染（逐字出现）→ 完成写库
- 生成中发送按钮变**停止方块**；停止后已收到的内容保留并标 `interrupted`
- 解析出的草案块自动渲染成**可编辑确认卡片**，确认即写入矛盾与行动
- 右上角模型状态实时显示「OpenAI 兼容 · deepseek-chat」或「未配置 AI · 去设置」
- 在示例会话里发消息会自动新建普通会话，不污染示例
